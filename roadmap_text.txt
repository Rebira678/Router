WHAT YOU WILL LEARN — PER PROJECT
Router (AI Inference Gateway) — Learning Outcomes
By the end of this project you will be able to:
Build a reverse proxy in Go from the standard library up, including streaming
(SSE) passthrough
Implement atomic distributed rate limiting (token bucket) using Redis + Lua,
and explain why naive GET/SET approaches are unsafe under concurrency
Design and implement a circuit breaker from scratch, and explain the
closed/open/half-open state machine
Handle automatic failover between multiple upstream providers under real
failure conditions
Design idempotent request handling to prevent double-processing on retries
Track and attribute cost/usage data per tenant in Postgres
Profile and eliminate goroutine leaks using pprof
Instrument a production service with Prometheus metrics and build a Grafana
dashboard
Containerize and deploy a multi-service local stack with Docker Compose, with
CI/CD via GitHub Actions

Retriever (RAG Ingestion Pipeline) — Learning Outcomes
By the end of this project you will be able to:
Design and implement a concurrent worker-pool architecture for batch APIbound workloads (embedding generation)

Work with vector embeddings and similarity search (cosine/L2 distance) using
Postgres + pgvector
Implement content-hash-based idempotency to prevent duplicate processing in
a data pipeline
Design and implement backpressure handling between pipeline stages using
bounded channels
Scale consumers horizontally and reason about coordination/duplication
across multiple instances
Tune vector index strategy (HNSW/IVFFlat) and measure its effect on query
latency
Implement hybrid (keyword + vector) search and explain when pure vector
search falls short
Instrument a data pipeline with distributed tracing (OpenTelemetry) and read a
trace waterfall to debug latency
Load test a search API and interpret p50/p95/p99 latency under increasing
load
Combined, cross-project outcome: you will be able to speak fluently, with your own
working code as evidence, about both halves of production AI infrastructure — the
real-time serving layer and the data ingestion/retrieval layer — which is a distinct
and rare combination in a junior-to-mid candidate pool.
